Implementation Plan
Phase A: Critical Fixes & Workflow Integrity (Issues 1–6, 13)
Goal: Fix broken features and ensure the core clinician workflow is correct before pilot.

Milestone A1 — SMS Removal & Email Verification (Issues 1, 2)

Remove all SMS-related UI text (helper text, labels, confirmations) across send dialogs
Debug and verify the Resend email integration — check API key, from address, and delivery flow end-to-end
Milestone A2 — Smart Language Selection & Processing Bug (Issues 3, 4)

Change language dropdown default from Spanish to the selected patient's preferredLanguage
Debug the "Processing failed" error for Tran Van Duc in the Riverside demo — likely a data/seeding issue with missing fields or tenant context
Milestone A3 — Approval Workflow Safeguards (Issues 5, 6)

Block "Save edits and final approve" unless translation is up-to-date (track a dirty/stale flag when simplified text is edited)
Add "Unapprove" / "Return to Review" action from the approved state so clinicians can go backward
Milestone A4 — Password Change Fix (Issue 13)

Fix password update so it actually persists the new hash
Add password format requirements (minimum length, complexity)
Reject password change if new password matches the current one
Phase B: UX & Navigation Polish (Issues 7–12, 14–16)
Goal: Smooth out friction points in the clinician and admin experience.

Milestone B1 — Upload & Input Flows (Issues 7, 8)

Add capture="environment" attribute to photo upload input for mobile camera access
Add patient demographic fields (name, DOB, language, email) to the dictate/paste flow so new patient records can be created inline
Milestone B2 — Navigation & Tab Switching (Issues 10, 11)

Refactor dashboard/analytics/settings tab switching to use CSS visibility toggling (similar to the multi-role switcher) instead of URL-based routing that causes reloads
Remove "Coming Soon" treatment from Analytics and Settings; render them as active tabs
Milestone B3 — Patient Experience Polish (Issues 9, 12, 14, 15, 16)

Auto-delete test patient records created via "send to myself" after the review session ends
Add reading level indicator/toggle to the simplification UI (show current level, optionally allow adjustment)
Change "Born 19XX" to display full DOB in admin patient detail
Bypass patient login for authenticated care team members using "View as Patient" — pass a session-verified bypass token
Add email-based team member invite flow as an alternative to manual username/password provisioning
Phase C: Analytics & Monitoring Enhancements (Issues 17–20)
Goal: Make analytics actionable and add operational monitoring.

Milestone C1 — Chart & Stats Improvements (Issues 17, 18)

Replace 100% stacked bar for care plan status with a more informative visualization (grouped bar chart or status funnel)
Add rolling time window filter (last 7 days / 30 days) to processing pipeline stats instead of all-time
Milestone C2 — Operational Alerts & TCM (Issues 19, 20)

Add stale care plan alerts: flag plans that haven't progressed to the next stage within a configurable duration (e.g., 48 hours) and surface them in the admin view
Audit and fix TCM compliance summary to ensure it calculates and displays meaningful data based on check-in responses and timelines
Master Sequencing
Phase A (Critical) ──→ Phase B (UX Polish) ──→ Phase C (Analytics)
  A1 → A2 → A3 → A4      B1 → B2 → B3          C1 → C2
Rationale: Phase A fixes broken core features that would block the pilot. Phase B smooths the experience for clinicians and admins. Phase C improves analytics and monitoring, which are important but not blocking. Within each phase, milestones are sequenced so dependencies flow naturally (e.g., fix email before removing SMS references that might mask the issue; fix navigation before promoting tabs out of "Coming Soon").
